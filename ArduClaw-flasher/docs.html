1. Pengantar

ArduClaw adalah AI Agent Runtime untuk board ESP32. Berbeda dengan firmware biasa yang perlu ditulis kode C++, ArduClaw memungkinkan kamu memberikan instruksi dalam bahasa sehari-hari (prompt) melalui web chat. AI akan menerjemahkan perintahmu menjadi aksi nyata di GPIO, MQTT, ADC, dan lainnya.

Saat ini masih beta — support board ESP32 DEV (ESP32-WROOM, ESP32-DevKitC). Board lain menyusul.

Prinsip: Daripada nulis kode digitalWrite(27, HIGH), cukup bilang “nyalakan lampu di pin 27” — AI Agent yang urus sisanya.

2. Mulai (Quickstart)

Yang kamu butuhkan:

  • Board ESP32 DEV (contoh: ESP32-WROOM-32, ESP32-DevKitC)
  • Kabel USB-A to Micro USB
  • Browser Chrome atau Edge (butuh Web Serial API)
  • Koneksi internet (untuk download firmware & API LLM)

Langkah-langkah:

  1. Flash firmware — buka Flash Firmware, connect USB, upload arduclaw-esp32-v02.bin
  2. Tekan RESET (EN) di board ESP32, tunggu 2 detik
  3. Connect Serial — klik Connect Serial di kolom WiFi
  4. Isi SSID & Password WiFi, klik Save
  5. Tunggu sampai status Connected — IP akan muncul
  6. Isi LLM Config — URL, API Key, Model, klik Save & Test
  7. Buka Dashboard — klik link IP yang muncul
  8. Mulai Chat — kirim prompt seperti “nyalakan LED di pin 27”
Catatan: Setelah flash, semua konfigurasi (WiFi, LLM, MQTT subscriptions, GPIO mode) tersimpan di NVS ESP32 — tidak hilang meski dimatikan. Hanya akan hilang jika di-re-flash dengan merged binary.

3. Flash Firmware

Gunakan halaman Flash Firmware untuk mengupload firmware ke ESP32:

  1. Klik Connect to Device — pilih port USB ESP32
  2. Pilih file .bin firmware — bisa pakai built-in atau upload manual
  3. Klik Flash — tunggu sampai selesai (progress bar)
  4. Setelah selesai, tekan RESET (EN) di board
  5. Lanjut ke konfigurasi WiFi & LLM via Serial

Fungsi lain:

  • Erase — menghapus semua flash (termasuk NVS)
  • Download — download firmware built-in untuk flashing manual

4. Konfigurasi WiFi

Setelah flash, board butuh koneksi WiFi untuk akses dashboard dan LLM:

  1. Pastikan Serial sudah connect (klik Connect Serial di kolom WiFi)
  2. Isi SSID dan Password
  3. Klik Save — board akan menyimpan dan mencoba konek
  4. Tunggu status Connected — IP akan muncul di banner
  5. Klik link IP untuk membuka Dashboard ESP32

Format command yang dikirim via Serial:

{"c":"ws","s":"nama_wifi","p":"password"}

Status WiFi bisa dicek dengan:

{"c":"wst"}

5. Konfigurasi LLM

ArduClaw butuh API LLM (OpenAI-compatible) untuk memproses prompt:

  1. Serial harus connect (klik Connect Serial di kolom LLM)
  2. Isi API URL — contoh: https://ai.sumopod.com/v1/chat/completions
  3. Isi API Key — dari provider LLM kamu
  4. Isi Model — contoh: gpt-4o-mini, claude-3-haiku, dll
  5. Klik Save Config
  6. Klik Test untuk verifikasi koneksi ke LLM

Format command ke Serial:

{"c":"llm_set","url":"https://...","key":"sk-...","model":"gpt-4o-mini"}
{"c":"llm_test"}
Provider yang bisa digunakan: OpenAI, Anthropic, Google Gemini (via OpenAI-compatible proxy), atau self-hosted LLM seperti vLLM, Ollama (dengan proxy OpenAI).

6. Chat / Prompt

Setelah semua terkonfigurasi, buka Dashboard ESP32 di browser dan masuk ke halaman Chat. Ini adalah antarmuka utama untuk berinteraksi dengan AI Agent.

Cara kerja:

  1. Ketik perintah dalam bahasa Indonesia atau Inggris di chat
  2. ESP32 kirim prompt ke LLM via API
  3. LLM menentukan skill apa yang harus dijalankan
  4. ESP32 eksekusi skill (GPIO, MQTT, dll) dan kirim hasilnya ke chat

Setiap chat tersimpan otomatis di localStorage browser — tidak hilang meski halaman di-refresh.

8. Skill GPIO

Skill untuk mengontrol pin GPIO ESP32.

gpio.write

Menulis nilai HIGH/LOW ke pin. Nilai bisa boolean atau string:

tool: gpio.write
args: {"pin":27,"value":true}
args: {"pin":27,"value":"on"}
args: {"pin":27,"value":"off"}
args: {"pin":27,"value":"high"}
args: {"pin":27,"value":"low"}

gpio.read

Membaca nilai digital pin:

tool: gpio.read
args: {"pin":26}
// return: {"pin":26,"value":1}

gpio.mode

Set mode pin: output, input, input_pullup, input_pulldown:

tool: gpio.mode
args: {"pin":26,"mode":"input_pullup"}

gpio.blink

Kedipkan pin sejumlah kali (synchronous, blocking):

tool: gpio.blink
args: {"pin":27,"on_ms":200,"off_ms":200,"count":5}

gpio.blink_start / gpio.blink_stop

Kedipkan pin kontinu di task terpisah (asynchronous):

tool: gpio.blink_start
args: {"pin":2,"on_ms":300,"off_ms":500}

tool: gpio.blink_stop
args: {"pin":2}

9. Skill Monitor

Monitor pin secara real-time di background task. Ketika trigger terpenuhi, skill lain dijalankan secara otomatis. Sangat berguna untuk membaca tombol atau sensor digital.

Parameter:

  • pin — nomor GPIO yang dimonitor
  • trigger — low, high, atau change
  • action — skill yang akan dijalankan (contoh: gpio.write)
  • action_args — argumen untuk skill (contoh: {"pin":27,"value":true})
  • poll — interval polling dalam ms (default 50)
  • debounce — waktu debounce dalam ms (default 30)
  • once — jika true, monitor hanya sekali lalu berhenti
tool: gpio.monitor
args: {"pin":26,"trigger":"low","action":"gpio.write","action_args":{"pin":27,"value":true},"poll":50,"debounce":30,"once":false}

Untuk menghentikan monitor:

tool: gpio.monitor_stop
args: {"pin":26}

10. Skill ADC

Membaca nilai analog dari pin ADC ESP32 (pin 32-39):

tool: adc.read
args: {"pin":34}
// return: {"pin":34,"raw":2048,"voltage":1.65}

11. Skill MQTT

MQTT memungkinkan ESP32 berkomunikasi dengan broker MQTT untuk IoT. Subscription bisa ditambah via chat dan akan tersimpan otomatis di NVS.

mqtt.subscribe

Subscribe ke topik MQTT dengan aksi tertentu. Gunakan {PAYLOAD} sebagai variable untuk payload MQTT:

tool: mqtt.subscribe
args: {"topic":"rumah/lampu","action":"gpio.write","action_args":{"pin":27,"value":"{PAYLOAD}"}}

Jika MQTT publish payload on ke topik rumah/lampu, maka {PAYLOAD} akan diganti on → gpio.write({"pin":27,"value":"on"}) → LED menyala.

mqtt.unsubscribe

Hapus subscription:

tool: mqtt.unsubscribe
args: {"topic":"rumah/lampu"}

Untuk hapus semua subscription:

tool: mqtt.unsubscribe
args: {"topic":""}

mqtt.list

Lihat daftar subscription aktif:

tool: mqtt.list
args: {}

mqtt.status

Cek status MQTT:

tool: mqtt.status
args: {}

Built-in MQTT Handler

ESP32 punya handler bawaan untuk topik hello/10219201/test. Payload on akan menyalakan GPIO 27, payload off akan mematikannya. Handler ini auto-subscribe saat broker connect — tidak perlu ditambah manual.

Persistence

Semua subscription MQTT tersimpan di NVS — tidak hilang saat reboot. Subscription akan di-restore dan di-sync ke broker setiap kali WiFi/MQTT connect. Hanya hilang jika di-re-flash dengan merged binary (karena NVS ikut terhapus).

12. Skill System

system.status

Menampilkan status ESP32: WiFi, IP, uptime, heap, jumlah skill, MQTT subscriptions:

tool: system.status
args: {}

system.clear_persist

Hapus semua data persist (monitor, GPIO mode, MQTT subs) tanpa reboot:

tool: system.clear_persist
args: {}

system.reset_factory

Factory reset — hapus semua NVS, restart ESP32. Setelah ini board seperti baru di-flash:

tool: system.reset_factory
args: {}

13. Dashboard Web

Setelah ESP32 connect WiFi, buka IP board di browser untuk mengakses dashboard. Tersedia halaman-halaman berikut:

  • Chat (/) — Antarmuka chat dengan AI Agent. Prompt dikirim ke LLM, skill dieksekusi langsung.
  • Dashboard (/dashboard) — Status sistem: WiFi, IP, uptime, heap, jumlah skill.
  • WiFi (/wifi) — Ganti SSID/Password WiFi dari web.
  • LLM (/llm) — Ganti konfigurasi LLM dari web.
  • MQTT (/mqtt) — Lihat, tambah, hapus subscription MQTT.
  • Skills (/skills) — Daftar semua skill yang terdaftar di ESP32.

Navigasi menggunakan menu horizontal di desktop — di mobile (≤600px) berubah menjadi hamburger menu dropdown.

14. Persistence (NVS)

ArduClaw menggunakan Preferences (NVS) di ESP32 untuk menyimpan data secara persisten. Data yang tersimpan:

  • WiFi config — SSID & password
  • LLM config — API URL, key, model
  • GPIO mode — mode pin yang diset via gpio.mode
  • Monitor config — konfigurasi gpio.monitor
  • MQTT subscriptions — daftar topic + action (max 20)

Data persist akan di-restore otomatis setiap boot. Catatan: flashing merged binary (offset 0) akan menghapus seluruh NVS. Untuk menjaga data, gunakan flashing parsial atau OTA update di masa depan.

15. Troubleshooting

Web Serial tidak muncul

Gunakan Chrome atau Edge versi terbaru. Web Serial tidak support di Firefox atau Safari.

Flash gagal / timeout

  • Coba ganti kabel USB — beberapa kabel hanya untuk charging, bukan data
  • Tekan dan tahan BOOT di ESP32 saat connecting, lepas setelah flash mulai
  • Turunkan baud rate di code (ganti 115200 jadi 921600 di connFlash)

Serial connect tapi ESP tidak merespons

  • Pastikan sudah tekan RESET (EN) setelah flash
  • Pastikan baud rate Serial 115200
  • Tunggu 5-10 detik, ESP butuh waktu boot

WiFi tidak bisa konek

  • Cek SSID & password — ESP32 tidak support WiFi 5GHz, harus 2.4GHz
  • Pastikan router tidak memblokir perangkat baru
  • Coba restart ESP32 (tekan RESET)

LLM test gagal

  • Cek API URL — harus OpenAI-compatible
  • Cek API Key — pastikan valid dan tidak expired
  • Cek model name — beberapa provider punya nama model berbeda
  • Pastikan ESP32 sudah connect WiFi

MQTT subscription hilang setelah flash ulang

Wajar — merged binary nge-flash dari offset 0 dan menghapus NVS. Tambah subscription lagi via chat setelah setup ulang. Subscription tetap aman di reboot biasa (tanpa re-flash).

Chat error “parse error”

Biasanya karena response LLM mengandung karakter yang tidak valid. Coba refresh halaman dan kirim prompt ulang. Jika terus terjadi, cek API Key atau coba model LLM lain.

16. Strapping Pins

ESP32 memiliki pin-pin strapping yang memengaruhi mode boot: GPIO 0, 2, 5, 12, 15. Mengubah state pin-pin ini saat boot bisa menyebabkan ESP32 gagal boot atau masuk mode flashing.

ArduClaw akan memperingatkan jika kamu menggunakan pin strapping, tapi tidak memblokir — tanggung jawab ada di kamu. Peringatan muncul di:

  • Serial console — [WARN] gpio.write: GPIO 0 adalah strapping pin!
  • Chat bubble — hasil skill akan ditambahi ⚠️Strapping pin!
Saran: Hindari pin strapping untuk project produksi. Gunakan GPIO 4, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33 yang aman.

17. FAQ

Apa bedanya ArduClaw dengan ESP-Claw?

ESP-Claw resmi dari Espressif hanya support board ESP32-S3 dengan RAM ≥ 1MB. ArduClaw support board ESP32 DEV yang paling banyak dijual di pasaran — ESP32-WROOM, ESP32-DevKitC, dan sejenisnya.

Apakah harus selalu online?

Ya — karena LLM dijalankan di cloud via API. Koneksi WiFi diperlukan setiap kali ingin mengirim prompt. Ke depannya bisa support LLM lokal (small model).

Berapa banyak skill yang bisa dipakai?

Maksimal 20 skill terdaftar. Saat ini sudah ada ~15 skill bawaan.

Berapa banyak MQTT subscription?

Maksimal 20 subscription aktif.

Aman kah pakai pin strapping?

Tidak disarankan untuk produksi. Tapi untuk prototyping/testing, ArduClaw hanya memberi peringatan — tidak memblokir. Kamu tetap bisa pakai pin 0, 2, 5, 12, 15.

Bagaimana cara reset total?

Kirim prompt “reset ke pengaturan pabrik” di chat, atau kirim {"c":"rst"} via Serial console.

Chat history ilang setelah refresh?

Tidak — chat tersimpan di localStorage browser. Tapi history spesifik per browser — tidak sync antar perangkat.

Bisa pakai ESP32-C3 / ESP32-S2 / ESP32-S3?

Saat ini baru support ESP32 DEV (dual-core Xtensa). Support board lain sedang dikembangkan. Jika kamu punya board lain, pantau update di website resmi.
