1. Introduction

ArduClaw is an AI Agent Runtime for the ESP32. Unlike traditional firmware where you write C++ code, ArduClaw lets you give instructions in natural language (prompts) through a web chat interface. The AI translates your commands into real actions on GPIO, MQTT, ADC, and more.

Currently in beta — supports ESP32 DEV boards (ESP32-WROOM, ESP32-DevKitC). More boards coming soon.

The idea: Instead of writing digitalWrite(27, HIGH), just say “turn on the LED at pin 27” — the AI Agent handles the rest.

2. Quickstart

What you need:

  • ESP32 DEV board (e.g. ESP32-WROOM-32, ESP32-DevKitC)
  • USB-A to Micro USB cable
  • Chrome or Edge browser (Web Serial API required)
  • Internet connection (for firmware download & LLM API)

Steps:

  1. Flash firmware — open Flash Firmware, connect USB, upload arduclaw-esp32-v02.bin
  2. Press RESET (EN) on the ESP32 board, wait 2 seconds
  3. Connect Serial — click Connect Serial in the WiFi column
  4. Enter SSID & Password, click Save
  5. Wait until status shows Connected — IP will appear
  6. Set LLM Config — URL, API Key, Model, click Save & Test
  7. Open Dashboard — click the IP link that appears
  8. Start Chatting — send prompts like “turn on LED at pin 27”
Note: After flashing, all configuration (WiFi, LLM, MQTT subscriptions, GPIO mode) is stored in the ESP32's NVS — it persists across power cycles. It will only be lost if you re-flash with the merged binary.

3. Flash Firmware

Use the Flash Firmware page to upload firmware to the ESP32:

  1. Click Connect to Device — select the ESP32 USB port
  2. Select the .bin firmware file — use built-in or upload manually
  3. Click Flash — wait for the progress bar to complete
  4. After completion, press RESET (EN) on the board
  5. Proceed to WiFi & LLM configuration via Serial

Other functions:

  • Erase — wipes all flash including NVS
  • Download — download the built-in firmware for manual flashing

4. WiFi Setup

After flashing, the board needs WiFi for dashboard and LLM access:

  1. Make sure Serial is connected (click Connect Serial in the WiFi column)
  2. Enter SSID and Password
  3. Click Save — the board will save and attempt to connect
  4. Wait for Connected status — IP will appear in the banner
  5. Click the IP link to open the ESP32 Dashboard

Command format sent via Serial:

{"c":"ws","s":"wifi_name","p":"password"}

Check WiFi status with:

{"c":"wst"}

5. LLM Setup

ArduClaw requires an OpenAI-compatible LLM API to process prompts:

  1. Serial must be connected (click Connect Serial in the LLM column)
  2. Enter the API URL — e.g. https://ai.sumopod.com/v1/chat/completions
  3. Enter your API Key from your LLM provider
  4. Enter the Model — e.g. gpt-4o-mini, claude-3-haiku, etc.
  5. Click Save Config
  6. Click Test to verify the LLM connection

Serial command format:

{"c":"llm_set","url":"https://...","key":"sk-...","model":"gpt-4o-mini"}
{"c":"llm_test"}
Supported providers: OpenAI, Anthropic, Google Gemini (via OpenAI-compatible proxy), or self-hosted LLMs like vLLM, Ollama (with OpenAI proxy).

6. Chat / Prompts

Once everything is configured, open the ESP32 Dashboard in your browser and go to the Chat page. This is the main interface for interacting with the AI Agent.

How it works:

  1. Type a command in Indonesian or English in the chat
  2. ESP32 sends the prompt to the LLM via API
  3. The LLM determines which skill to execute
  4. ESP32 executes the skill (GPIO, MQTT, etc.) and returns the result

Chat history is automatically saved in the browser's localStorage — it persists across page refreshes.

8. GPIO Skills

Skills for controlling ESP32 GPIO pins.

gpio.write

Write HIGH/LOW to a pin. Value can be boolean or string:

tool: gpio.write
args: {"pin":27,"value":true}
args: {"pin":27,"value":"on"}
args: {"pin":27,"value":"off"}
args: {"pin":27,"value":"high"}
args: {"pin":27,"value":"low"}

gpio.read

Read a pin's digital value:

tool: gpio.read
args: {"pin":26}
// returns: {"pin":26,"value":1}

gpio.mode

Set pin mode: output, input, input_pullup, input_pulldown:

tool: gpio.mode
args: {"pin":26,"mode":"input_pullup"}

gpio.blink

Blink a pin a number of times (synchronous, blocking):

tool: gpio.blink
args: {"pin":27,"on_ms":200,"off_ms":200,"count":5}

gpio.blink_start / gpio.blink_stop

Continuous blink in a separate task (asynchronous):

tool: gpio.blink_start
args: {"pin":2,"on_ms":300,"off_ms":500}

tool: gpio.blink_stop
args: {"pin":2}

9. Monitor Skill

Monitor a pin in real-time via a background task. When the trigger condition is met, another skill is automatically executed. Useful for reading buttons or digital sensors.

Parameters:

  • pin — GPIO pin number to monitor
  • trigger — low, high, or change
  • action — skill to execute (e.g. gpio.write)
  • action_args — arguments for the skill (e.g. {"pin":27,"value":true})
  • poll — polling interval in ms (default 50)
  • debounce — debounce time in ms (default 30)
  • once — if true, monitor fires once then stops
tool: gpio.monitor
args: {"pin":26,"trigger":"low","action":"gpio.write","action_args":{"pin":27,"value":true},"poll":50,"debounce":30,"once":false}

To stop monitoring:

tool: gpio.monitor_stop
args: {"pin":26}

10. ADC Skill

Read analog values from ESP32 ADC pins (pins 32-39):

tool: adc.read
args: {"pin":34}
// returns: {"pin":34,"raw":2048,"voltage":1.65}

11. MQTT Skills

MQTT enables the ESP32 to communicate with an MQTT broker for IoT applications. Subscriptions can be added via chat and are automatically saved to NVS.

mqtt.subscribe

Subscribe to an MQTT topic with a specific action. Use {PAYLOAD} as a variable for the MQTT payload:

tool: mqtt.subscribe
args: {"topic":"home/light","action":"gpio.write","action_args":{"pin":27,"value":"{PAYLOAD}"}}

If someone publishes payload on to topic home/light, then {PAYLOAD} is replaced with on → gpio.write({"pin":27,"value":"on"}) → LED turns on.

mqtt.unsubscribe

Remove a subscription:

tool: mqtt.unsubscribe
args: {"topic":"home/light"}

Remove all subscriptions:

tool: mqtt.unsubscribe
args: {"topic":""}

mqtt.list

List active subscriptions:

tool: mqtt.list
args: {}

mqtt.status

Check MQTT connection status:

tool: mqtt.status
args: {}

Built-in MQTT Handler

The ESP32 has a built-in handler for the topic hello/10219201/test. Payload on turns GPIO 27 on, payload off turns it off. This handler auto-subscribes when the broker connects — no manual setup needed.

Persistence

All MQTT subscriptions are saved to NVS — they survive reboots. Subscriptions are restored and synced to the broker every time WiFi/MQTT reconnects. Only lost if you re-flash with the merged binary (which erases NVS).

12. System Skills

system.status

Display ESP32 status: WiFi, IP, uptime, heap, skill count, MQTT subscriptions:

tool: system.status
args: {}

system.clear_persist

Clear all persistent data (monitors, GPIO mode, MQTT subs) without reboot:

tool: system.clear_persist
args: {}

system.reset_factory

Factory reset — wipes all NVS, restarts ESP32. Board will be like freshly flashed:

tool: system.reset_factory
args: {}

13. Web Dashboard

Once the ESP32 is connected to WiFi, open the board's IP in a browser to access the dashboard. The following pages are available:

  • Chat (/) — AI Agent chat interface. Prompts sent to LLM, skills executed in real-time.
  • Dashboard (/dashboard) — System status: WiFi, IP, uptime, heap, skill count.
  • WiFi (/wifi) — Change SSID/Password from the web.
  • LLM (/llm) — Change LLM configuration from the web.
  • MQTT (/mqtt) — View, add, and remove MQTT subscriptions.
  • Skills (/skills) — List of all registered skills.

Navigation uses a horizontal menu on desktop — on mobile (≤600px) it becomes a hamburger dropdown menu.

14. Persistence (NVS)

ArduClaw uses Preferences (NVS) on the ESP32 to store data persistently. Stored data includes:

  • WiFi config — SSID & password
  • LLM config — API URL, key, model
  • GPIO mode — pin modes set via gpio.mode
  • Monitor config — gpio.monitor configurations
  • MQTT subscriptions — topic + action list (max 20)

Persistent data is automatically restored on every boot. Note: flashing the merged binary (offset 0) will erase the entire NVS. To preserve data, use partial flashing or OTA updates in the future.

15. Troubleshooting

Web Serial not showing up

Use the latest version of Chrome or Edge. Web Serial is not supported in Firefox or Safari.

Flash fails / timeout

  • Try a different USB cable — some cables are charge-only, not data
  • Hold BOOT on the ESP32 while connecting, release after flash starts
  • Lower the baud rate (change 115200 to 921600 in connFlash)

Serial connected but ESP not responding

  • Make sure you pressed RESET (EN) after flashing
  • Ensure baud rate is 115200
  • Wait 5-10 seconds, ESP needs time to boot

WiFi won't connect

  • Check SSID & password — ESP32 doesn't support 5GHz WiFi, must be 2.4GHz
  • Make sure your router isn't blocking new devices
  • Try restarting the ESP32 (press RESET)

LLM test fails

  • Check the API URL — must be OpenAI-compatible
  • Check the API Key — make sure it's valid and not expired
  • Check the model name — different providers use different names
  • Make sure the ESP32 is connected to WiFi

MQTT subscriptions lost after re-flash

This is expected — the merged binary flashes from offset 0 and erases NVS. Re-add subscriptions via chat after setup. Subscriptions are safe across normal reboots (without re-flashing).

Chat shows “parse error”

Usually caused by invalid characters in the LLM response. Try refreshing the page and sending the prompt again. If it persists, check your API Key or try a different LLM model.

16. Strapping Pins

ESP32 has strapping pins that affect boot mode: GPIO 0, 2, 5, 12, 15. Changing these pins' state during boot can cause boot failure or force flash mode.

ArduClaw will warn when you use strapping pins, but it does not block you — use at your own risk. Warnings appear in:

  • Serial console — [WARN] gpio.write: GPIO 0 is a strapping pin!
  • Chat bubble — skill results are appended with ⚠️Strapping pin!
Recommendation: Avoid strapping pins for production projects. Use GPIO 4, 16, 17, 18, 19, 21, 22, 23, 25, 26, 27, 32, 33 instead.

17. FAQ

What's the difference between ArduClaw and ESP-Claw?

ESP-Claw by Espressif only supports ESP32-S3 boards with ≥ 1MB RAM. ArduClaw supports the widely available ESP32 DEV boards — ESP32-WROOM, ESP32-DevKitC, and similar.

Does it require a constant internet connection?

Yes — the LLM runs in the cloud via API. WiFi is required to send prompts. Local (on-device) LLM support may come in the future.

How many skills can be registered?

Maximum 20 registered skills. Currently there are ~15 built-in skills.

How many MQTT subscriptions?

Maximum 20 active subscriptions.

Is it safe to use strapping pins?

Not recommended for production. For prototyping/testing, ArduClaw only warns — it doesn't block you. Pins 0, 2, 5, 12, 15 will still work.

How do I factory reset?

Send the prompt “factory reset” in chat, or send {"c":"rst"} via the Serial console.

Does chat history survive a page refresh?

Yes — chat is saved in the browser's localStorage. However, history is per-browser — it does not sync across devices.

Can I use ESP32-C3 / ESP32-S2 / ESP32-S3?

Currently only ESP32 DEV (dual-core Xtensa) is supported. Support for other boards is in development. Check the official website for updates.
